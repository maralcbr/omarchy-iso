# Private Limine image qualification

This branch admits one private diagnostic product, `omarchy-mx-mac-limine-private`. It does not make schema-4 candidates available through the default GRUB product, change the canonical integration branch, publish an update channel, or enroll the development signer into an installed system's update policy.

The caller must select `--mode diagnostic`, the private product, a signed schema-4 candidate, and a signed schema-2 Limine dependency snapshot. Candidate and dependency authentication still use the builder's checked-in public policy. Before builder package trust changes, the private admission check binds the runtime source revision, exact U-Boot candidate archive name and SHA-256, and the public signing-policy SHA-256 to the product. The ordinary product continues to refuse schema 4. The private product has a separate package-cache suffix and distinct output filename.

The kernel remains the frozen `linux-asahi` 7.1.13 platform input. The m1n1 branding lock is measured from m1n1 1.6.1, all 110 device trees in the pinned kernel package, and the exact candidate U-Boot binary. Reconstruction follows the pinned `update-m1n1`: concatenate m1n1 and the sorted device trees, append GNU `gzip -c` output for `u-boot-nodtb.bin` with its package timestamp, and append no optional configuration. Reconstructing the original platform U-Boot first reproduces the existing baseline input hash exactly; the same method then measures the candidate. The patcher still verifies every original logo region and the complete unbranded and branded boot hashes.

The finalized stage retains the configured GRUB file as an inactive transition artifact, generates and validates the Apple UKI, activates the runtime Limine leaf, and validates the resulting loader, menu, kernel, initramfs and conversion hooks. The product's emitted backend is `asahi-limine`. Its active boot contract comes from the validated Limine loader, UKI and menu; the retained GRUB file is hashed but does not promise a post-activation fallback. The ZIP verifier additionally binds the exact authenticated ALARM Limine EFI bytes, requires the menu and UKI, and rejects occupied fresh-conversion staging. Root and factory identity cleanup and first-owner markers remain governed by the integration finalizer.

A successful source test or package build does not qualify the image. Qualification still needs the complete authenticated package transaction, finalized image and artifact checks, disposable VM boot/conversion/owner/reset tests where feasible, and later physical Apple model testing. The private output remains diagnostic and ineligible for a release catalog.
